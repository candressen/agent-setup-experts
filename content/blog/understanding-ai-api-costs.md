## Why This Cost Is Separate

ASE charges for strategy, setup, integrations, testing, and launch. API fees are different. Those are usage-based charges billed directly by providers like OpenAI and Anthropic when your live workflows send prompts, process messages, or generate outputs.

Keeping provider spend separate makes the offer cleaner for small businesses. You can see the setup investment clearly, then control usage as your team adopts the workflows.

## What an AI API Actually Charges For

Most providers bill based on usage, not a flat unlimited website fee. In practice, your cost usually depends on:

- how many conversations or automations run
- how much text, data, or context each workflow sends
- which model powers the workflow
- whether the agent handles simple classification, full conversations, summaries, or more advanced reasoning

A lightweight FAQ or lead-routing workflow usually costs far less than a more involved assistant reviewing long threads, documents, or back-and-forth conversations.

## Why Costs Vary by Business

Two businesses can buy the same ASE package and have very different provider bills.

For example:

- A 5-agent starter setup with modest lead volume may stay relatively low-cost because the workflows run only when new leads or appointments come in.
- A larger team using multiple support, reporting, and follow-up agents every day will naturally create more monthly API usage.
- A custom workflow that processes long documents, transcripts, or high message volume can cost more than a simple reminder or routing workflow.

That is why we do not bury provider fees inside a one-size-fits-all setup package.

## How ASE Keeps This Manageable

When we set up a workflow, we aim for practical business value first, not unnecessary model usage. That usually means:

- choosing the lightest model that can do the job reliably
- keeping prompts focused instead of bloated
- adding approvals where human review makes sense
- avoiding wasteful automations that run constantly without business value

The goal is a working system that stays credible financially as it grows.

## A Simple Way to Think About It

Your ASE package covers building and launching the system. Your API bill covers how much the live system gets used.

That is similar to paying a team to install equipment or software, then paying the underlying provider for ongoing usage.
